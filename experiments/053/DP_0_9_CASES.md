# Experiment 053 — DP 0.9 Minimum Sufficient Support / Valuation holdout

## M01 — Residual classifier
A finite classifier has exactly three mutually exclusive and collectively exhaustive classes A, B, C. Exact tests for A and B are available. If both are false, the represented partition authority entails C. The semantic model must still retain C as a class.

## M02 — Non-partition lookalike
Three alerts A, B, C often occur separately, but the source neither says they are mutually exclusive nor exhaustive. C carries cases not identified by A or B.

## M03 — Downstream fallback
Precomputation X supplies an exact bound consumed by a fast path. If X is absent, an exact fallback explores more states but returns the identical required answer, witness, and audit record for the same admissible inputs.

## M04 — Hidden side effect
Precomputation X also produces a required signed certificate included in the declared output contract. The fallback reproduces the answer but not the certificate.

## M05 — Minimal, not minimum
Support S is irreducible under single-node deletion. The declared candidate family contains unexamined alternative factorizations. No global size comparison has been completed.

## M06 — Fewer transitions profile
Two exact sufficient topologies preserve the same target contract. A supplied valuation profile has one criterion only: fewer load-bearing transitions. A uses 7, B uses 4.

## M07 — Runtime reversal
Two exact sufficient topologies preserve the target. A uses 4 transitions and measures 18 ms; B uses 7 transitions and measures 11 ms under a frozen workload. The only supplied preference is lower wall-clock time.

## M08 — Unranked tradeoff
Two exact sufficient topologies are available. A uses less time and more peak memory; B uses more time and less peak memory. No weights, thresholds, or lexicographic priority are supplied.

## M09 — Approximate shortcut
A cheaper candidate returns an estimate within 1% while the declared target requires exact integer output.

## M10 — Narrowed domain
A smaller topology is exact only for nonnegative inputs. The declared objective covers all signed inputs.

## M11 — QU-sensitive support
Qualified QU retains two admissible realizations. Support X is unnecessary in one realization and necessary in the other.

## M12 — DTS-sensitive substitution
Two paths reach the same endpoint. One emits a required intermediate signed transition record; the other does not. The declared objective includes that transition obligation.

## M13 — Authorized implication
The represented governing theory explicitly supplies A -> B and A. The support graph currently computes B independently.

## M14 — Familiar but unauthorized inference
A discovery guide suggests testing contraposition, but the supplied governing logic has no rule authorizing it in this case.

## M15 — Objective change
Node X is unnecessary for objective O1 but is the only source of a required provenance field in objective O2.

## M16 — Valuable optional accelerator
Removing accelerator X preserves exact correctness. Measured cost of X is 2 units and it avoids 20 units downstream under the supplied workload profile.

## M17 — Negative-value accelerator
Removing accelerator X preserves exact correctness. X costs 15 units and avoids only 3 units downstream under the supplied workload profile.

## M18 — Consumer boundary
A local component consumes Y, but the declared target lies two stages later and a bypass plus exact closure can establish the full target without Y. No optimization hint identifies Y in advance.

## M19 — Anti-overfit branch
A three-branch topology resembles a residual classifier, but branch C contributes a unique required witness bit not derivable from A or B.

## M20 — Full-stack authority
A support candidate depends on one QU region and one DTS transition obligation. The question is whether DP 0.9 may choose a convenient QU realization or erase the transition difference to obtain a smaller support.
