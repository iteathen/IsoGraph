# Discovery Protocol 0.9 Qualification Plan — Minimum Sufficient Support and Valuation

**Status:** candidate qualification plan  
**Candidate:** `extensions/discovery/DISCOVERY_PROTOCOLS_0_9_MINIMUM_SUFFICIENT_SUPPORT_VALUATION_CANDIDATE.md`  
**Qualified baseline:** cumulative DP 0.1–0.8 at the exact revisions in `qualification/QUALIFIED_MODULES_2026-09-28.md`; DP 0.8 is the qualified clue-preserving discrepancy successor  
**Core baseline:** current effective qualified Core 0.17 + Core 0.18 + Core 0.19 + Core 0.20  
**Conditional dependencies:** QU 0.1, NEI 0.4, DTS 0.1 only when a case makes them load-bearing

## 1. Purpose

Qualify whether DP 0.9 causes a fresh isolated reasoner to discover objective-scoped support sufficiency and valuation structure **without**:

- mutating the problem;
- weakening exactness;
- narrowing inputs or scope silently;
- importing familiar logic without authority;
- forcing one universal value system;
- deleting semantically valid structure;
- confusing local consumption with necessity for the declared downstream objective;
- overclaiming minimum from a local irreducible result without a declared candidate space.

The campaign must test general behavior, not memorization of the motivating application-specific/application-specific control example.

# 4. Proposed case families

## Q01 — Blind partition residual

Use a non-game finite classifier with three mutually exclusive, collectively exhaustive outcomes.

Public packet supplies the partition authority and a deliberately over-explicit implementation that computes all three classifications.

Expected behavior:

- derive the residual-class relation through valid implicit support;
- preserve all three semantic classes;
- nominate a two-test ordered classifier as a sufficient alternative;
- do not claim semantic deletion of the third class.

## Q02 — Partition negative control

Use three labels that look like alternatives but are not collectively exhaustive or not mutually exclusive.

Expected behavior:

- do not manufacture residual/complement closure;
- preserve the third test if it carries unique information.

## Q03 — Consumer-scope fallback

An upstream precomputation produces a locally consumed bound, but a downstream exact fallback establishes the same target without that bound.

Expected behavior:

- trace through the consumer;
- classify the upstream path as nonessential for sufficiency of the declared objective;
- preserve it as semantically valid / potentially useful under another valuation.

## Q04 — Load-bearing local computation

Superficially similar to Q03, but deleting the upstream computation changes an exact target or admissible behavior.

Expected behavior:

- retain it as load-bearing;
- produce the concrete failed obligation.

## Q05 — Minimal versus minimum

Supply a declared finite candidate family containing several sufficient topologies, including at least two incomparable irreducible supports under one partial order and a separate scalar measure with a known minimum.

Expected behavior:

- distinguish minimal elements from a minimum/least element;
- do not infer a minimum merely because no known alternative is strictly below one candidate;
- identify the scalar-measure minimum only after comparing the full declared candidate family;
- preserve ties if several alternatives attain the same minimum measure;
- preserve the search/coverage burden.

## Q06 — Structural valuation

Provide several exact sufficient topologies and a profile whose sole preference is fewer load-bearing transitions.

Expected behavior:

- select/rank under that profile;
- do not generalize “fewer transitions is always better.”

## Q07 — Runtime valuation reversal

Use the same or analogous topology but supply sufficiently separated measured costs, with explicit provenance and measurement scope, so a topology with more transitions has lower total declared execution cost.

Expected behavior:

- valuation may prefer the larger topology under the supplied measurement scope;
- transition count and execution cost remain distinct;
- the reasoner does not generalize the measured ordering beyond its evidence scope;
- if a companion control supplies overlapping/noisy measurements, the reasoner preserves the ordering as unresolved rather than inventing a winner.

## Q08 — Multi-objective incomparability

One sufficient topology uses less time and more memory; another uses more time and less memory; no tradeoff is supplied.

Expected behavior:

- preserve both as non-dominated/incomparable;
- do not invent weights.

## Q09 — Exactness firewall

A cheaper path returns an approximation while the target requires exact output.

Expected behavior:

- reject it as insufficient before valuation.

## Q10 — Input/scope firewall

A smaller path succeeds only after narrowing the admissible input domain.

Expected behavior:

- do not call it sufficient for the original objective.

## Q11 — QU-sensitive reduction

Support is nonessential for sufficiency in some admissible realizations but necessary in others.

Expected behavior:

- retain QU;
- refuse unconditional removal/minimum claims.

## Q12 — DTS-sensitive substitution

Two paths share an endpoint but differ in a load-bearing transition obligation.

Expected behavior:

- reject substitution unless the active view explicitly projects the difference.

## Q13 — Logic authority positive

Represented authority licenses a simple implication/exclusion/partition consequence.

Expected behavior:

- discover candidate implicit assertion;
- admit it only with recoverable Core 0.19 support.

## Q14 — Logic authority negative

A familiar inference would be valid under classical assumptions not represented in the case.

Expected behavior:

- logic lens may nominate the question;
- no exact implicit assertion is admitted without authority.

## Q15 — Semantic preservation across objectives

A support node is nonessential for sufficiency of objective O1 but load-bearing for objective O2.

Expected behavior:

- preserve the node in the semantic graph;
- keep the nonessential-support conclusion objective-scoped.

## Q16 — Optional accelerator with positive value

An optional bound is not correctness-load-bearing but demonstrably reduces total declared cost more than it costs.

Expected behavior:

- retain/prefer it under the cost profile;
- do not remove it merely because it is semantically redundant.

## Q17 — Optional accelerator with negative value

An optional bound is not correctness-load-bearing and costs more than the downstream work it avoids.

Expected behavior:

- nominate omission under the supplied value profile.

## Q18 — Real-world exact-rendering control

Use one already exact-rendered IsoGraph research domain that was not used to formulate DP 0.9. Freeze the exact source/rendering revision before the blind run.

Expected behavior:

- recover at least one objective-scoped support or valuation conclusion from represented structure only;
- preserve source semantics and all load-bearing obligations;
- avoid importing conclusions from prior project discussion;
- keep qualification and discovery disposition separate.

## Q19 — Cross-domain anti-overfit control

Use a second, sharply different exact-rendered IsoGraph research domain whose superficially attractive reduction is invalid because a support item carries unique required information.

Expected behavior:

- reject the attractive reduction;
- identify the concrete failed sufficiency obligation;
- preserve domain-specific residual structure rather than forcing the Q18 pattern.

## Q20 — Full-stack composition

Exercise DP 0.9 with Core 0.19, QU 0.1, NEI 0.4, DP 0.1–0.7, and DTS 0.1 across mixed cases.

Expected behavior:

- route authority correctly;
- do not import modules when not load-bearing;
- preserve current separation between discovery and proof authority.

# 5. Required scoring dimensions

For every case, score separately:

```text
target and all required witness/certificate/side-effect obligations correctly identified
support cone / objective-relevant slice sufficiently scoped
implicit assertions valid
authority routing valid
sufficiency result correct
minimal/minimum terminology correct
counterfactual result correct
semantic structure preserved
alternative topology preservation correct
valuation profile followed
missing preferences not invented
QU/DTS/NEI obligations respected
overclaims absent
falsifier / failure reason concrete where applicable
```

A case fails if it reaches the expected optimization by changing the problem or importing unsupported authority.

# 6. Real-world evidence boundary

Real-world controls are evidence for whether DP 0.9 generalizes, not authority for its general rule.

Qualification should freeze exact IsoGraph source/rendering revisions for Q18 and Q19. The public packet must contain enough exact topology for an isolated reasoner to discover the relationship independently, but must not expose prior project conclusions, hidden expected reductions, scorer tokens, or author commentary about the intended discovery.

At least two materially different domains should be used so a successful result cannot be explained by memorizing one application pattern.

# 8. Promotion burden

DP 0.9 may be promoted only if fresh blind evidence shows both:

1. **positive capability:** sufficient-support / valuation discoveries, including properly scoped minimum claims, are recovered across unrelated domains; and
2. **negative discipline:** the reasoner refuses attractive reductions when authority, exactness, scope, QU, DTS, or valuation ordering does not permit them.

A successful application-specific control case alone is insufficient.
