# Experimental Inquiry 0.1 Qualification Plan

**Status:** candidate qualification plan  
**Candidate:** `extensions/experimental/EXPERIMENTAL_INQUIRY_0_1_CANDIDATE.md`  
**Required warrant authority:** exact qualified DP 0.10 revision  
**Core baseline:** current effective qualified Core through 0.20  
**Conditional dependencies:** QU 0.1, NEI 0.4, DTS 0.1 when load-bearing

## Purpose

Qualify whether an isolated reasoner can construct and revise useful experiments under an explicitly incomplete model without arbitrary search, hidden-answer import, QU collapse, evidence leakage, or proof-authority overreach.

## Freeze and isolation

Freeze all candidate/dependency bytes, public cases, experiment-construction contracts, hidden assertions, output schema, case order, and provider policy before execution.

Do not provide the correct variable set or complete experiment in advance.

## Required case families

Use unrelated domains covering:

1. no experiment without warrant;
2. partial clue -> discovered scope;
3. justified narrow scope;
4. required interaction retained;
5. gap-derived new dimension;
6. QU-sensitive experiment without realization selection;
7. open-world reserve kept separate from QU;
8. targeted plus open observation channel;
9. unexpected material output preserved;
10. model break -> scope reopened;
11. adaptive lineage recorded;
12. post-hoc boundary -> fresh confirmation required;
13. structural-event alignment under DTS;
14. narrow negative result limited to tested coverage;
15. external simulator/instrument provenance;
16. stopping instead of random fishing;
17. lawful valuation only after validity;
18. evidence returned to correct IsoGraph authority owner.

## Promotion burden

A module-level pass requires both constructive capability and restraint. A run that discovers the intended variable but invents unsupported authority, loses unexpected outputs, silently reuses adaptive evidence as confirmation, or treats omitted dimensions as excluded does not qualify.

After EI 0.1 qualifies, run a fresh full-stack integration campaign with the then-qualified DP 0.9 and DP 0.10 revisions.
